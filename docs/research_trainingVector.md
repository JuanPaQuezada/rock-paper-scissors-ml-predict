 ## Architectural Research & Concurrency Rationale
 
-The architecture of this simulated Reinforcement Learning environment is heavily anchored in the Task Parallel Library (TPL) and its Dataflow components. By utilizing TPL Dataflow, the system establishes a safe, non-blocking pipeline for state ingestion, feature transformation, inference, and training updates.
-
-Implementing this level of continuous concurrency introduces the critical challenge of shared memory management. In this system, the training pipeline continuously updates the mathematical weights of the model while the UI remains responsive. To guarantee correctness, shared mutable state is protected with synchronization primitives such as `ReaderWriterLockSlim`, ensuring that historical vectors and transition statistics can be read and updated safely.
-
-Furthermore, the design consciously avoids the performance degradation associated with over-parallelization. While the TPL provides powerful abstractions like `Parallel.For` for data parallelism, applying unnecessary parallelism to a small, sequential decision loop would introduce scheduling overhead without measurable benefit. For that reason, the architecture reserves parallel execution for independent, high-cost tasks and keeps the core prediction loop deterministic and lightweight.
-
-Finally, this strict concurrent separation dictates the absolute boundaries of how background processes interact with the presentation layer. A fundamental constraint of multithreaded design is that background workers must never directly mutate UI controls; instead, they publish results through safe marshaling or message-passing mechanisms, allowing the UI thread to remain the sole owner of presentation state.

Implementing this level of continuous concurrency introduces the critical challenge of shared memory management, since the training pipeline continuously updates the mathematical weights of the model while the UI remains responsive, so shared mutable state must be protected with synchronization primitives such as `ReaderWriterLockSlim` to ensure that historical vectors and transition statistics can be read and updated safely without race conditions. At the same time, the design consciously avoids the performance degradation associated with over-parallelization, because although the TPL provides powerful abstractions like `Parallel.For` for data parallelism, applying unnecessary parallelism to a small sequential decision loop would introduce scheduling overhead without measurable benefit, therefore the architecture reserves parallel execution for independent high-cost tasks and keeps the core prediction loop deterministic and lightweight. From a data science and research perspective, the hybrid flow is structured so that C# remains the system of record for the move history, storing the vector and the sequence of plays in memory in a controlled and thread-safe way, then only delegating the statistical query to R when the system needs a forecast; in that step, C# packages the history and sends it through an interop mechanism such as R.NET or a lightweight script bridge, R receives the array and uses the `markovchain` package to compute the transition matrix and the MLE estimate, and then returns a single compact prediction such as the most probable next user move, after which C# immediately regains control, uses that prediction in the inference engine to choose the counter-move, updates the vector in the training engine by computing the TD error, and refreshes the UI from the C# side only. This strict concurrent separation also dictates the absolute boundaries of how background processes interact with the presentation layer, because a fundamental constraint of multithreaded design is that background workers must never directly mutate UI controls; instead, they publish results through safe marshaling or message-passing mechanisms, allowing the UI thread to remain the sole owner of presentation state, while R can either shut down after returning the prediction or remain available for the next query without being required to retain session memory.
